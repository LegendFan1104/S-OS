# 近期内核修改记录（2026-06-23）

> **注意：本文记录的内核修改尚未合并到当前代码仓库的主分支，下文描述的代码状态可能与仓库实际内容存在差异。**

这份文档记录本轮围绕 `sleep/nanosleep`、时钟中断、SIGALRM、EXT4 小 I/O 热路径，以及链表健壮性做的实际修改。

## 1. sleep / nanosleep 路径修正

### 1.1 用户态 `nanosleep` ABI 修正

此前用户态 `sys_nanosleep` 的声明和封装使用的是 `timeval_t`，而内核实现按 `timespec_t` 解析，ABI 不一致。现已统一改为 `timespec_t`。

涉及文件：

- `user/include/def.h`
- `user/include/usercall.h`
- `user/include/userlib.h`

### 1.2 睡眠线程状态修正

此前 `sleep_on_chan()` 会把进程状态设为 `SLEEPING`，但线程状态仍保留为 `t_RUNNABLE`，进程级和线程级状态不一致。现已调整为：

- 睡眠时：`p->state = SLEEPING`，`p->main_thread->state = t_SLEEPING`
- 唤醒时：同时恢复为 `RUNNABLE / t_RUNNABLE`

相关唤醒路径已同步修改：

- `wakeup()`
- `kill()`
- `kill_all()`
- `tgkill()`

涉及文件：

- `kernel/process.c`

### 1.3 `nanosleep` 被信号打断的处理

此前 `sleep()` 只检查 `p->killed`，没有像 `clock_nanosleep()` 那样检查未屏蔽的 pending signal。现已补齐：若存在未屏蔽 pending signal，会返回 `-EINTR`，并写回剩余时间。

涉及文件：

- `kernel/syscall.c`

## 2. 时钟中断与 SIGALRM 路径调整

### 2.1 RISC-V 定时器重装前移

此前 `set_next_timeout()` 在 `timer_tick()` 末尾才调用，只要 `timer_tick()` 中间卡住，后续 tick 就不会再来。现已改为在 RISC-V 时钟中断一进入 `devintr()` 时就先重装下一次超时。

涉及文件：

- `hsai/hsai_trap.c`

### 2.2 `timer_tick()` 缩成最小路径

此前 `timer_tick()` 除了 `ticks++` 和 `wakeup(&ticks)` 外，还会遍历整个 `pool[NPROC]` 扫描定时器到期进程，硬中断路径过重。现已改为：

- 保留 `ticks++`
- 保留 `wakeup(&ticks)`
- 不再扫描全进程表
- 改为只遍历“已启用 timer 的进程链表”

为此增加了：

- `proc_t.timer_elem`
- `timer_active_list`
- `timer_sync_process_alarm()`
- `timer_cancel_process_alarm()`

`sys_settimer()` 在更新 `timer_active/alarm_ticks` 后，会同步活跃链表；`freeproc()` 在回收进程前会将其从链表摘除。

涉及文件：

- `include/kernel/process.h`
- `include/kernel/timer.h`
- `kernel/timer.c`
- `kernel/syscall.c`
- `kernel/process.c`

### 2.3 SIGALRM 到期显式唤醒

此前 `refresh_process_timer()` 只设置 `sig_pending |= SIGALRM`，不主动唤醒睡眠进程。现已改为：若进程因 `sleep/nanosleep/等待锁` 处于 `SLEEPING`，则在 SIGALRM 到期时直接恢复为 `RUNNABLE`，并同步恢复主线程状态。

涉及文件：

- `kernel/timer.c`

## 3. EXT4 小 I/O 热路径优化

### 3.1 去掉 `vfs_ext4_read/write` 每次 syscall 的页分配

此前 `vfs_ext4_read()`、`vfs_ext4_readat()`、`vfs_ext4_write()` 每次用户态 I/O 调用都会 `kalloc()` / `kfree()` 一页缓冲。对 `stdio` 的 `putc/getc` 这类高频小 I/O 非常不友好。现已改为使用固定大小的栈缓冲（`VFS_EXT4_IOBUF_SIZE = 512`）。

涉及文件：

- `kernel/fs/vfs_ext4.c`

### 3.2 延后 `mtime/ctime` 更新时间

此前每次 `vfs_ext4_write()` 成功写入后，都会在热路径上更新 `mtime/ctime`。现已改为：

- 写路径仅标记 `f_time_dirty`
- `close()` regular file 时再统一提交时间戳

涉及文件：

- `include/kernel/fs/file.h`
- `kernel/fs/file.c`
- `kernel/fs/vfs_ext4.c`

### 3.3 缓存“是否目录”信息

此前 `fileclose()` 会再次根据路径调用 `vfs_ext4_is_dir()` 判断是目录还是普通文件。现已在打开时缓存 `f_is_dir`，关闭时直接使用，减少一次额外路径查询。

涉及文件：

- `include/kernel/fs/file.h`
- `kernel/fs/file.c`
- `kernel/fs/vfs_ext4.c`

### 3.4 `ext4_fwrite()` 的保守 fast path

此前 `ext4_fwrite()` 无论是否只是覆盖已有数据，都会先 `ext4_trans_start()`，结束时再 `ext4_trans_stop()`。现已改为：

- 若本次写入不会扩展文件大小，则不启动事务
- 仅当写入可能扩文件时才走原有事务路径

这个改动只优化“纯覆盖写”，不改变扩文件、分配新块时的原有语义。

涉及文件：

- `kernel/fs/ext4.c`

## 4. 链表与伙伴系统防护

为排查 `panic:[list.c:250] is_interior(elem)`，补了一层链表健壮性防护：

- 增加 `list_elem_linked()`
- `list_insert()` 只允许插入“当前未挂链”的节点
- `list_remove()` 后主动清空 `prev/next`
- buddy 合并前要求伙伴节点不仅元数据显示为空闲，而且 `elem` 真实挂在空闲链表上

涉及文件：

- `include/kernel/fs/list.h`
- `kernel/fs/list.c`
- `kernel/pmem.c`

## 5. 当前仍未支持的点

`fcntl22` 依赖 POSIX 记录锁：

- `F_GETLK`
- `F_SETLK`
- `F_SETLKW`
- `struct flock`
- 阻塞等待
- 死锁检测并返回 `EDEADLK`

当前内核尚未实现这套机制。现有 `fcntl()` 只支持：

- `F_DUPFD`
- `F_DUPFD_CLOEXEC`
- `F_GETFD`
- `F_SETFD`
- `F_GETFL`
- `F_SETFL`

因此当前不能认为系统支持 `fcntl22`。
