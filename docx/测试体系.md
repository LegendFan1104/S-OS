# 测试体系

项目：SOS (SuperOS)

队伍 ID：T2026104869910625

本文档说明 SOS 的测试层次、测试配置、测试运行方法和 LTP 适配策略。

## 测试层次

```
┌────────────────────────────┐
│    iozone (性能基准)        │  ← 最上层，验证文件系统稳定性与性能
├────────────────────────────┤
│    LTP (Linux Test Project) │  ← 系统调用兼容性全面验证
├────────────────────────────┤
│    busybox 命令测试          │  ← 基础命令: ls, ps, kill, free, df, hwclock
├────────────────────────────┤
│    basic 基础测试            │  ← open/read/write/close/mmap/mkdir/stat
├────────────────────────────┤
│    smoke 冒烟测试            │  ← 最低层：内核能否启动并执行 initcode
└────────────────────────────┘
```

## 测试配置

通过 `TEST_PROFILE` 变量控制测试范围：

| TEST_PROFILE | RISC-V 行为 | LoongArch 行为 | 说明 |
|-------------|-------------|----------------|------|
| `smoke` | 冒烟测试 | 冒烟测试 | 默认，最小验证 |
| `probe` | 探测测试 | smoke | 较完整验证 |
| `submit` | 提交测试 | 提交测试 | 竞赛提交配置 |
| `ltp-musl` | LTP + musl | LTP + musl | LTP 全套 |
| `ltp-glibc` | LTP + glibc | LTP + glibc | LTP 全套 |

Makefile 快捷目标：
```bash
make submit-rv        # TEST_PROFILE=submit-rv（RISC-V 提交模式）
make probe-rv         # TEST_PROFILE=probe-rv（探测）
make ltp-musl-la      # LoongArch + musl LTP
make ltp-glibc-la     # LoongArch + glibc LTP
make ltp-musl-rv      # RISC-V + musl LTP
make ltp-glibc-rv     # RISC-V + glibc LTP
make ltp-manifest-rv  # 生成 RISC-V LTP 清单头文件
```

## 测试流程

### initcode → test.sh

用户态入口 `initcode` 启动后执行流程：

```
initcode (user/riscv/user.c 或 user/loongarch/user.c)
  → 打开 /dev/console (fd 0, 1, 2)
  → execve("/musl/busybox", ["busybox", "sh", "test.sh"], env)
    → test.sh 根据 TEST_PROFILE 决定执行哪些测试
      ├─ smoke:    echo "smoke test passed"
      ├─ basic:    执行 /glibc/basic/* 或 /musl/basic/*
      ├─ busybox:  ls /, ps, free, kill -l, df
      ├─ ltp:      执行 LTP 用例列表
      └─ iozone:  执行 iozone 基准测试
```

### QEMU 运行命令

**RISC-V 测试**：
```bash
qemu-system-riscv64 -machine virt -kernel kernel-rv -m 1G -nographic -smp 1 \
  -bios default \
  -drive file=sdcard-rv.img,if=none,format=raw,id=x0 \
  -device virtio-blk-device,drive=x0,bus=virtio-mmio-bus.0 \
  -no-reboot \
  -device virtio-net-device,netdev=net \
  -netdev user,id=net \
  -rtc base=utc \
  -drive file=disk.img,if=none,format=raw,id=x1 \
  -device virtio-blk-device,drive=x1,bus=virtio-mmio-bus.1
```

**LoongArch 测试**：
```bash
qemu-system-loongarch64 -kernel kernel-la -m 1G -nographic -smp 1 \
  -drive file=sdcard-la.img,if=none,format=raw,id=x0 \
  -device virtio-blk-pci,drive=x0 \
  -no-reboot \
  -device virtio-net-pci,netdev=net0 \
  -netdev user,id=net0 \
  -rtc base=utc \
  -drive file=disk-la.img,if=none,format=raw,id=x1 \
  -device virtio-blk-pci,drive=x1
```

## LTP 测试适配

### 清单文件

| 文件 | 用途 |
|------|------|
| [rv_musl_skip.txt](tools/ltp/rv_musl_skip.txt) | 需要跳过的测试用例（编译期排除） |
| [rv_musl_groups.txt](tools/ltp/rv_musl_groups.txt) | 测试用例分组（按功能分类） |
| [rv_musl_runtime_skip.txt](tools/ltp/rv_musl_runtime_skip.txt) | 运行时动态跳过的测试 |
| [ltp_rv_musl_manifest.h](user/riscv/ltp_rv_musl_manifest.h) | RISC-V LTP 编译清单头文件 |

### LTP 测试目录结构

```
sdcard-extract/
├── riscv/
│   ├── glibc/
│   │   ├── basic/        基本 syscall 测试
│   │   ├── busybox_cmd.txt busybox 命令列表
│   │   ├── ltp/          LTP 测试二进制
│   │   │   ├── bin/      测试脚本与报告模板
│   │   │   └── testcases/ 测试用例目录
│   │   │       └── data/  测试数据文件
│   │   └── text.txt      测试说明
│   └── musl/             同上结构（musl 编译版本）
└── loongarch/
    ├── glibc/             同上结构
    └── musl/              同上结构
```

### 添加新 LTP 用例

1. 将 LTP 二进制放入 `sdcard-extract/<arch>/<libc>/ltp/testcases/` 对应目录
2. 更新 `user/riscv/ltp_rv_musl_manifest.h` 注册新用例
3. 如需跳过，加入 `rv_musl_skip.txt`
4. 运行时跳过（条件性失败），加入 `rv_musl_runtime_skip.txt`

## iozone 测试

iozone 是业界标准的文件 I/O 性能基准，覆盖以下测试维度：

| 测试 | 说明 |
|------|------|
| Write | 顺序写入新文件 |
| Re-write | 写入已存在的文件 |
| Read | 顺序读取已存在的文件 |
| Re-read | 重复读取最近读过的文件 |
| Random Read | 随机偏移读取 |
| Random Write | 随机偏移写入 |
| Strided Read | 跨步读取（跳跃式） |
| Fsync | 每次写入后 fsync |

### 当前 iozone 状态

- RISC-V：前 7 个用例通过（Write/Re-write/Read/Re-read/Random Read/Random Write/Strided Read）
- LoongArch：调试进行中

iozone 测试过程中发现并修复的 EXT4 bug：
- Extent 树节点满时分裂失败
- 并发写入时的数据竞争
- 块分配器边界条件

## 内核内部测试 (`kernel/test.c`)

提供内核态单元测试入口，通过编译宏控制，用于验证 Buddy System、页表操作等基础组件。
