# 决赛一阶段内核适配开发记录

本文记录在适配过程中发现并修复的内核缺陷，按问题发现阶段分为两部分：基础系统调用与运行时修复、面向复杂用户态程序的内核增强。

## 一、基础系统调用与内核机制修复

### 1.1 系统调用实现与 ABI 修正

**`statfs` 用户指针处理**  
`sys_statfs()` 原实现错误地将用户空间输出地址当作输入字符串进行复制，修正为：先在内核栈上清零 `statfs` 结构，由文件系统填充后，通过 `copyout` 安全写入用户空间。

**`stat` 结构布局补齐**  
`struct kstat` 缺少 Linux RISC-V `stat` 结构尾部的保留字段，导致 glibc 读取结构末尾时越界或得到错误布局。补全该结构体，保持与 Linux ABI 一致。

**文件类型与设备节点映射**  
`filestat()` 为字符设备、管道等特殊文件填充正确的文件类型、块大小和默认字段；增加镜像中 `/dev/tty`、`/dev/console`、`/dev/null`、`/dev/zero` 等设备号到内核内部设备类型的转换，保证用户态打开的 Linux 设备节点能够进入正确的设备读写路径。

**ext4 文件系统修复**  
- `ext4_fstat` 在块数量为零时不再触发除零异常。  
- ext4 分区可见容量从 4GB 扩展到 16GB，确保大镜像后部文件可被正常访问。

### 1.2 信号、线程和进程生命周期

**信号处理**  
- `sys_rt_sigprocmask()` 按实际信号集结构大小执行 `copyin/copyout`，并正确处理 `uset` 为空的只读/修改语义。  
- `sys_rt_sigaction()` 增加 Linux 内核结构与内核内部结构之间的转换逻辑，检查信号编号范围，避免跨 ABI 直接复制。  
- 修正信号屏蔽集合的保留位逻辑，防止可屏蔽信号被错误清除或保留。

**线程与进程标识**  
- `sys_gettid()` 返回当前线程的 tid，不再错误地统一返回进程 pid。  
- `sys_set_tid_address()` 改为保存用户传入的地址作为 `clear_child_tid`，不再误将地址内容当作地址使用。  
- 增加 `sigaltstack` 支持，在进程结构中保存备用信号栈地址、大小及标志。

**`clone` 与线程实现**  
- `clone()` 重新实现 Linux 风格的返回路径，正确设置子进程返回值、用户栈、TLS、`CLONE_CHILD_CLEARTID` 以及父子 tid 地址。  
- `CLONE_VM` 线程路径为子线程分配完整独立内核栈，设置 TLS，并在持有进程锁的条件下加入线程队列。  
- 进程退出时，先保存进程 trapframe，再清理线程 futex 状态和内核栈，避免主线程 trapframe 或线程内核栈被重复释放。  
- `exec` 执行前将同一进程中的其他线程置为僵尸状态并重置线程计数，防止动态链接器在旧线程上下文中运行。

### 1.3 内存与随机数

- `sys_getrandom()` 从仅支持固定 8 字节改为支持任意长度，分块写入用户缓冲区。  
- `growproc()` 成功时返回 0，修正原先扩展成功却返回错误码的问题。  
- `sys_brk()` 在将绝对地址转换为有符号增长量前检查收缩与溢出情况，防止无符号减法被解析为超大内存申请。  
- 增加 RISC-V `hwprobe` 系统调用，对 glibc 的查询返回内核承诺的基础能力，而非直接返回错误。

### 1.4 启动与底层机制

- RISC-V 启动时由主 hart 清理 `.bss`，其他 hart 等待内核初始化完成；启动栈按 CPU 数量分配并放置在不覆盖当前启动栈的区域。  
- 开启 RISC-V 外部中断和软件中断，保证 VirtIO 块设备操作完成后可被及时处理。  
- trapframe 中的内核栈顶使用完整的 `KSTACKSIZE`，并正确保存当前 hart id。  
- QEMU virt 平台下使用可用启动时间和默认频率初始化定时器，避免访问不存在的 Goldfish RTC MMIO 地址导致启动失败。  
- LoongArch 的 PCI、VirtIO 及启动诊断输出统一由 `FINAL_DEV_DIAG` 控制，防止正常测试串口被设备扫描信息淹没。

## 二、面向复杂用户态的内核修复

在运行基于 glibc 的动态链接程序、编译器工具链等复杂负载时，内核暴露出更深层的 ABI 兼容性、地址空间管理及文件系统正确性问题，以下为修复内容。

### 2.1 终端接口 ABI 修复

glibc 程序启动时频繁出现 `*** stack smashing detected ***` 并终止。定位到 `TCGETS` 实现：内核 termios 结构中的 `c_cc` 数组按 32 个控制字符定义，返回结构大小为 52 字节，而 Linux 内核 termios ABI 规定 `NCCS` 为 19，正确大小为 36 字节。glibc 的 ioctl 包装层预留了符合 Linux 的用户结构，内核返回多余字节会覆盖其栈保护值。  
修复时将内核 `c_cc` 改为 19 字节，`TCGETS` 通过 `copyout()` 返回 36 字节，与 Linux 内核布局对齐。此后 glibc 工具可正常通过终端初始化阶段。

### 2.2 动态链接与 ELF 加载

**软链接解析**  
镜像中动态库常使用版本软链接（如 `libatomic.so.1` -> 具体 ELF 文件）。`openat()` 原先直接返回软链接文件描述符，动态链接器读取到目标路径字符串而报 `invalid ELF header`。  
增加 `resolve_open_symlinks()`，在最终打开普通文件前解析绝对或相对软链接，限制解析层数并检测循环，确保 `mmap` 和 ELF 加载始终拿到目标文件。

**执行文件加载**  
`exec` 增加执行路径解析与 shebang 检测：不再仅依据文件名后缀，而是检查 `#!`；脚本交由 busybox 执行时将解析后的脚本路径置于正确 argv 位置；栈上补充 `AT_EXECFN` 辅助向量，并修正 argc、argv、envp 布局。

**多段 ELF 装载与权限**  
原先逐段调用 `uvm_grow()` 处理 `PT_LOAD`，遇到共享页或段间空隙时会扰乱页表和 VMA。实现 `elf_load_segments()`，装载分为三步：  
1. 遍历所有 `PT_LOAD`，按页建立完整映射并清零；  
2. 仅复制每段 `p_filesz` 字节，`p_memsz` 剩余部分保持零（BSS）；  
3. 汇总同一页上各段权限，最后一次性设置读、写、执行属性。  
同时，在 RISC-V 上显式设置 A/D 位，在 LoongArch 上显式设置 `PTE_D`，避免依赖硬件自动更新访问/脏位。

### 2.3 地址空间与 VMA 管理重写

重写了进程地址空间管理逻辑，解决动态链接器和编译器对复杂映射模式的需求：

- `mmap_choose_addr()` 改为在所有 VMA 间的空隙中选取地址，而非仅基于单个 VMA 推算。  
- 新增 `vma_remove_range()` 统一处理区间删除，能够将原 VMA 拆分为前后两段，并为后段修正文件偏移。  
- `MAP_FIXED` 行为修正：先删除重叠区域对应的 VMA 和页表，再建立新映射，满足动态链接器覆盖保留区的语义。  
- `munmap()` 将非页对齐的范围扩展到完整页边界，并在拆分后刷新 TLB。  
- 文件映射使用 `readat()` 按文件偏移读取数据，避免改变共享文件对象的当前偏移。  
- `mprotect()` 按实际页边界更新权限；LoongArch 清除写权限时同步清除脏位。  
- `mmap()` 对文件末尾不足一页的区域仅读取文件实际剩余字节，其余页面保持零。  
- 删除了早期绕过动态链接器而硬编码的映射地址，完全由 ELF 装载和 VMA 逻辑建立页面。

### 2.4 虚拟文件系统与系统调用补充

glibc 运行时会读取 `/proc/self/maps` 和 `/proc/self/exe` 以获取自身映射布局。原实现返回固定内容，修改为根据进程的实际 `exe_path`、ELF 范围、栈及 VMA 动态生成 `maps` 内容，并针对当前进程返回 `/proc/self/exe` 的正确路径。  
补充或修正了下列系统调用语义：  
- `fstatat()` 的软链接跟随行为；  
- `faccessat()` 对 glibc 兼容标志的处理；  
- `mprotect()` 参数溢出与页范围检查；  
- `prlimit64()` 返回 stack、address space、data、core、file size 等资源的合理默认值；  
- 以及 glibc 依赖的 `writev`、`stat`、`fstat`、`readlinkat`、`sigaltstack`、`riscv_hwprobe` 等入口。

### 2.5 设备与内存管理修复

**`/dev/null` 写入行为**  
`devnullwrite()` 原先对非零长度写入返回 0，glibc 将其视为短写而反复重试，导致脚本无法继续。改为直接返回请求长度 `n`，表示所有数据已被消费，与 Linux `/dev/null` 行为一致。

**buddy allocator 链表损坏**  
工具链退出阶段触发 `list.c` 的 `is_interior` 断言失败。分析发现伙伴块的位图标记为空闲，但对应节点已在先前的合并中被摘链（`prev/next` 为空），再次 `list_remove()` 时误将脱链节点当作有效链表元素操作，导致内存损坏。  
增加 `buddy_elem_is_linked()` 检查，仅当前后指针能够互相指回当前节点时才允许合并与删除；对明确为空链接的节点重新插入对应空闲链表；检测到异常链接则中止本次合并，避免继续解引用不可信地址。该修复解决了大规模程序退出及大量 `mmap` 释放时的链表破坏问题。

### 2.6 LoongArch 架构特定修复

**地址空间扩展**  
glibc 工具链的静态程序、动态链接器、共享库及 `mmap` 区域会使用高于 2GB 的用户地址，而原 `MAXUVA` 被限制为 `0x80000000`，导致合法地址判定为非法，`mmap` 无法找到可用空间。将用户地址上限扩展至 `0x1000000000`，并同步修正 VMA 和页表地址检查逻辑。

**缺页异常与扩展启用**  
缺页异常处理增加 LoongArch PME（Page Modification Exception）支持；在已映射页发生写缺页时补充 `PTE_D` 位；启动时使能 LSX/LASX 向量扩展，满足 glibc/jemalloc 等组件对 SIMD 上下文的需求。

**ELF 解释器路径与辅助向量**  
修正 LoongArch glibc 解释器路径为 `/glibc/lib/ld-linux-loongarch-lp64d.so.1`，并将 `loadaux()` 返回值改为 64 位，防止用户栈辅助向量地址被高位截断。ELF 可写段及 `mmap` 页全部显式设置 `PTE_D`，确保动态链接器能够正常执行重定位和 TLS 初始化。

**ext4 文件读取正确性**  
在运行大型动态链接程序时，发现读取到的文件内容与预期不符，经逐层定位发现以下缺陷：  
- `ext4_blocks_get_direct` 处理连续物理块时，未正确停止于块号为 0 的边界，导致将稀疏文件空洞处继续映射到无效物理块；  
- 物理块号 0 被解释为有效块，将镜像超级块（块 0）数据填充到用户文件，造成内容错误；  
- 文件尾部不足一个块时未按实际长度读取，且空洞部分未填零。  
修复后：连续读取在块号 0 处停止当前段；对块号 0 明确作为空洞填零；不足一块的尾部按实际字节数读取并补零。

**VirtIO 块设备 DMA 隔离**  
为排除 DMA 一致性问题，对 LoongArch VirtIO 磁盘驱动进行加固：  
- 使用独立 DMA 缓冲区，请求完成后再将数据复制到 bcache，避免 bcache 页面与设备 DMA 窗口重叠；  
- VirtIO 队列、描述符和状态通过 DMWIN1 非缓存别名访问；  
- 以状态字节轮询替代 `used->id` 直接比较，消除首请求误判；  
- 在提交队列、读取状态及数据复制位置加入必要内存屏障。  
上述改动在后续验证中保证了文件块读取的正确性，并为真实缓存硬件提供了正确的所有权同步边界。

### 2.7 LoongArch pthread 线程模型与同步原语修复

在 RISC-V 上，较多 pthread 用例可以正常运行，但 LoongArch 上出现线程创建后行为异常、TLS 访问错误、条件变量等待不返回、线程取消失败以及线程池耗尽等问题。对比两个架构的 musl 汇编入口和内核线程调度路径后，问题并非单纯由线程池容量不足引起，而是由多个相互独立的线程 ABI 和同步语义缺陷叠加造成。

**LoongArch `clone` 参数顺序不一致**

内核内部的 `clone_thread()` 使用统一的参数顺序：`stack、ptid、tls、ctid、flags`。RISC-V musl 的 `clone` 包装器向系统调用传递的寄存器顺序是：

```text
flags, stack, ptid, tls, ctid
```

而 LoongArch musl 按本架构的系统调用约定传递：

```text
flags, stack, ptid, ctid, tls
```

原内核直接使用同一套参数解释，导致 LoongArch 新线程把 `ctid` 当成 TLS 地址写入 `tp`，同时把真正的 TLS 地址当成 `clear_child_tid`。具体后果包括：

- 新线程的 `__pthread_self()` 指向错误位置；
- musl 的线程本地变量、取消标志和 tid 字段被错误读取；
- 线程退出时可能向 TLS 区域写零，破坏用户态线程控制块；
- `pthread_join()` 等待的 tid 清除地址不正确。

在 `sys_clone()` 入口增加架构相关的参数归一化：RISC-V 继续使用原有顺序，LoongArch 将收到的第四、第五个参数交换为内部使用的 `tls、ctid`，之后再调用公共的 `clone_thread()` 或 `clone()`。这样不修改两个内部 clone 实现，也不影响已经通过的 RISC-V 线程用例。

**LoongArch 上下文保存寄存器修正**

LoongArch trapframe 同时保存用户线程指针 `tp` 和帧指针 `fp`。原 `copycontext_from_trapframe()` 将 `trapframe->tp` 写入内核上下文的 `context.fp`，把 TLS 地址当成了内核上下文的帧指针。线程第一次从调度器切换到 `forkret()` 时会恢复这个错误值，可能破坏内核 C 函数的栈帧和寄存器约定。

修复为从 `trapframe->fp` 保存帧指针，`trapframe->tp` 只负责在返回用户态时恢复 TLS。该修改只位于 LoongArch 分支，RISC-V 上下文保存逻辑保持不变。

**线程退出和线程资源回收**

pthread 的 `pthread_exit()` 使用 `SYS_exit`，但线程组中一个线程退出时不能直接销毁整个进程。内核增加独立的 `thread_exit()` 路径：

1. 清零 `clear_child_tid` 并唤醒等待该地址的 joiner；
2. 清理当前线程的 futex 等待状态；
3. 将当前线程标记为僵尸，只减少线程计数，不改变同一进程中其他线程的地址空间；
4. 通过调度器切换到其他线程；
5. 等调度器已经离开该线程的内核栈后，再释放 trapframe、独立内核栈并将线程重新放入空闲线程链表。

原实现在线程仍可能使用自己的内核栈时就回收资源，且主线程的状态清理与进程 trapframe 释放存在重复处理风险。现在由调度器延迟回收僵尸线程，避免释放当前执行栈和重复释放 trapframe。线程池容量同时从 1024 扩展到 2048，减少大量 pthread 创建/销毁测试中的资源耗尽，但线程回收仍是保证长期运行的主要机制。

**futex 超时和调度条件修正**

原 futex 超时路径将用户传入的秒、纳秒转换成微秒，但调度器使用的是架构时钟计数，两个单位不一致；调度器还使用“当前时间加固定大范围”的判断，导致定时等待线程过早被选中，表现为超时立即返回或锁竞争时序异常。

修复后，futex 将相对超时时间转换为：

```text
当前 r_time() + tv_sec * CLK_FREQ + tv_nsec * CLK_FREQ / 1e9
```

调度器只在 `awakeTime <= r_time()` 时选择定时线程。与此同时，futex 等待的用户地址和时间结构复制失败分别返回 `EFAULT`，非法纳秒字段返回 `EINVAL`，用户值与期望值不一致返回标准的 `EAGAIN`，删除了单线程等待时直接修改用户 futex 值的临时绕过逻辑，恢复 futex 的基本语义。

**条件变量广播与 requeue**

musl 的条件变量广播会调用 `FUTEX_WAKE`，并使用 `val = -1` 表示唤醒全部等待者；条件变量和互斥锁之间的交接还使用 `FUTEX_REQUEUE`，其中 `val` 是唤醒数量，第四个参数是重新排队数量。原实现只接受正数唤醒数量，并把 requeue 的参数解释成了错误的字段，导致广播无法唤醒等待者，或者条件变量等待链被破坏。

现在 `futex_wake()` 将负数唤醒数量解释为不设上限；`futex_requeue()` 分别处理唤醒数量和迁移数量，返回实际受影响的等待者数量，并在唤醒线程时同步将所属进程置为可运行。这样保留了 musl 条件变量通过 barrier 逐个转移等待者的设计，不把所有等待者错误地一次唤醒或迁移。

**线程级信号状态与 pthread 取消**

原信号屏蔽字和待处理信号只有进程级字段，多个 pthread 修改信号屏蔽字时会互相覆盖；`sys_tkill()` 找到目标线程后仍固定返回 `-1`，因此 musl 将成功的 `pthread_cancel()` 误判为 `EPERM`。此外，目标线程阻塞在 futex、nanosleep 或 poll 时，内核没有将它唤醒。

在线程结构中增加独立的信号屏蔽字和 pending signal：

- 新线程继承创建线程的信号屏蔽字；
- `rt_sigprocmask` 修改当前线程的屏蔽字；
- `tgkill/tkill` 将目标信号记录到目标线程，而不是无条件写入进程公共状态；
- 找到目标线程时返回 0，线程不存在时返回 `ESRCH`，信号号非法时返回 `EINVAL`；
- 目标线程处于 futex 定时等待或普通睡眠时，清理等待项并重新加入调度；
- futex、nanosleep、poll 返回前检查未屏蔽的线程 pending signal，并返回 `EINTR`。

### 2.8 RISC-V 时钟频率校准

在比较两个架构的 pthread 和 BuildStorm 运行时间时，发现 RISC-V 的 sleep、futex 超时、调度时间片以及系统运行时间都明显偏慢。检查 `r_time()` 的实现后确认，RISC-V 读取的是 QEMU `virt` 平台的 `time` CSR，该计数器使用的是平台 timebase 频率，而不是 CPU 主频。

原实现直接把 RISC-V 的计数器频率固定为 100MHz。当前 QEMU `virt` 设备树提供了 `google,goldfish-rtc`，实际计数器频率约为 10MHz，因此所有依赖 `CLK_FREQ` 的时间换算都产生了约十倍误差：定时器中断间隔、`nanosleep`、futex 超时、`clock_gettime` 和 `sysinfo.uptime` 都会表现为时间流逝过慢。LoongArch 已经通过 LS7A RTC 对 `rdtime.d` 进行校准，RISC-V 也应使用同一设计。

具体修改包括：

- 在 RISC-V 平台布局中声明 QEMU `virt` 的 Goldfish RTC 基地址 `0x101000`，以及低 32 位和高 32 位时间寄存器；
- 在内核页表中映射 RTC 所在的 MMIO 页面，保证打开 Sv39 分页后 `timer_init()` 仍能访问设备；
- 将 Goldfish RTC 的纳秒计数转换为 Unix 秒，用于设置启动墙上时间；
- 读取 64 位 RTC 值时先后读取两次高位寄存器，若高位在读取过程中发生变化则重读，避免低位溢出时拼出错误时间；
- 移除 RISC-V 独立的固定频率分支，使 RISC-V 和 LoongArch 共用“等待 RTC 秒变化、读取两次架构计数器、用计数差得到实际频率”的校准流程；
- 保留原有频率范围检查和默认值回退，避免 RTC 读数异常时把非法值传递给所有时间换算路径。

校准结果写入统一的 `timer_freq`，后续定时器中断、进程定时器、futex、睡眠系统调用和时间查询接口均继续通过 `CLK_FREQ` 使用该值，因此没有改变各接口的逻辑，只修正了底层计数器单位。
