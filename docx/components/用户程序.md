# 用户程序与测试脚本

项目：SOS (SuperOS)

队伍 ID：T2026104869910625

本文档说明 SOS 的用户态运行时：initcode 入口程序、系统调用封装、编译流程和测试脚本。

## 用户态目录结构

```
user/
├── include/
│   ├── def.h              用户态基础定义（NULL、bool、基本类型）
│   ├── userlib.h          用户态库函数声明
│   └── usercall.h         系统调用封装函数声明
├── riscv/
│   ├── user.c             RISC-V initcode 入口程序
│   ├── usys.S             RISC-V 系统调用跳板（ecall 指令）
│   ├── user_initcode.ld   RISC-V 用户程序链接脚本
│   ├── Makefile           RISC-V 编译规则
│   └── ltp_rv_musl_manifest.h  LTP 测试清单（RISC-V musl）
├── loongarch/
│   ├── user.c             LoongArch initcode 入口程序
│   ├── usys.S             LoongArch 系统调用跳板（syscall 0 指令）
│   ├── user_initcode.ld   LoongArch 用户程序链接脚本
│   └── Makefile           LoongArch 编译规则
└── build/
    ├── rv_init_code.h     编译后的 RISC-V initcode 字节数组
    └── la_init_code.h     编译后的 LoongArch initcode 字节数组
```

## initcode 入口程序

### RISC-V (`user/riscv/user.c`)

```c
void _start()
{
    // 1. 打开 /dev/console 作为 fd 0, 1, 2
    int fd0 = open("/dev/console", O_RDWR);
    int fd1 = open("/dev/console", O_RDWR);
    int fd2 = open("/dev/console", O_RDWR);

    // 2. 构造参数
    char *argv[] = {"busybox", "sh", "test.sh", NULL};
    char *envp[] = {"PATH=/musl:/glibc", NULL};

    // 3. 执行 busybox sh 运行测试脚本
    execve("/musl/busybox", argv, envp);

    // 4. 失败处理
    exit(-1);
}
```

### LoongArch (`user/loongarch/user.c`)

流程与 RISC-V 一致，使用 LoongArch syscall 指令（`syscall 0`）。

## 系统调用跳板

### RISC-V (`user/riscv/usys.S`)

```asm
// 每个 syscall 封装函数：
//  1. 加载 syscall 编号到 a7
//  2. ecall
//  3. ret

usys_open:
    li a7, 56          // SYS_openat (Linux RV64)
    ecall
    ret
```

### LoongArch (`user/loongarch/usys.S`)

```asm
// LoongArch syscall 使用 syscall 0 指令
// syscall 编号同样放在 $a7

usys_open:
    li.d $a7, 56       // SYS_openat (Linux LA64)
    syscall 0
    ret
```

## 编译流程

1. `user/riscv/Makefile` / `user/loongarch/Makefile` 编译 `user.c` + `usys.S`
2. 链接脚本 `user_initcode.ld` 将代码从地址 0 开始排列
3. `objcopy` 生成原始二进制 `user.bin`
4. `objdump` 反汇编为 `.asm` 文件（调试用）
5. `xxd` 或类似工具将二进制转换为 C 数组 `unsigned char init_code[]`
6. 数组写入 `build/rv_init_code.h` 或 `build/la_init_code.h`
7. 内核通过 `#include "rv_init_code.h"` / `#include "la_init_code.h"` 嵌入 initcode

## 测试脚本

initcode 执行 `busybox sh test.sh`。`test.sh` 根据编译宏 `TEST_PROFILE` 决定测试范围：

```
TEST_PROFILE=smoke:
  echo "smoke" → 验证内核基本启动

TEST_PROFILE=submit:
  执行完整的 busybox 命令测试 + LTP 用例

TEST_PROFILE=ltp-musl:
  执行 musl 编译的 LTP 全覆盖用例

TEST_PROFILE=ltp-glibc:
  执行 glibc 编译的 LTP 全覆盖用例
```

## 构建命令

```bash
# 编译并反汇编 initcode
make user

# 仅编译 initcode
make initcode

# 生成 RISC-V 汇编列表
make show_initcode_rv   # → build/rv_init_code.asm

# 生成 LoongArch 汇编列表
make show_initcode_la   # → build/la_init_code.asm
```

## 后续风险

- initcode 是静态编译的固定程序，修改测试逻辑需要重新编译内核镜像。
- 用户态库（`userlib.h`）目前功能有限，复杂测试程序需要预编译的 Linux 二进制。
- LoongArch 和 RISC-V 的 syscall 编号体系不同（Linux LA64 vs RV64），维护两份 `usys.S` 可能产生不一致。
- 测试脚本 `test.sh` 的内容未在源码树中，位于磁盘镜像内部，需要单独维护。
