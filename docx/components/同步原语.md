# 同步原语

项目：SOS (SuperOS)

队伍 ID：T2026104869910625

本文档说明 SOS 内核中使用的同步原语：自旋锁、睡眠锁、睡眠/唤醒机制，以及它们的使用约束。

## 自旋锁 (`kernel/spinlock.c`)

### 数据结构

```c
struct spinlock {
    uint locked;        // 1=已锁定, 0=空闲
    char *name;         // 锁名称（调试用）
    cpu_t *cpu;         // 持有锁的 CPU（多核时用于死锁检测）
};
```

### 接口

```c
void initlock(struct spinlock *lk, const char *name); // 初始化锁
void acquire(struct spinlock *lk);                     // 获取锁（关闭中断，自旋等待）
void release(struct spinlock *lk);                     // 释放锁（恢复中断）
int  holding(struct spinlock *lk);                     // 检查当前 CPU 是否持有该锁
void push_off();                                       // 关闭中断（嵌套计数）
void pop_off();                                        // 恢复中断（嵌套计数）
```

### 实现要点

- `acquire()` 使用 RISC-V `amoswap` / LoongArch `amswap` 原子交换指令。
- 获取锁前通过 `push_off()` 关闭中断（`intr_off()`），防止中断处理中的死锁。
- `release()` 后通过 `pop_off()` 恢复中断状态。
- `push_off`/`pop_off` 使用 `cpu->noff` 嵌套计数，支持嵌套的锁获取。
- `holding()` 用于 `assert(holding(&p->lock))` 防御性检查。

### 使用约束

- 自旋锁只用于短临界区（微秒级）。
- 持有自旋锁时禁止睡眠（`sleep_on_chan`）或调用调度器。
- 多锁获取必须按固定顺序，避免死锁。
- 中断处理中只使用自旋锁，不能使用睡眠锁。

### 全局锁实例

| 锁 | 保护对象 | 文件 |
|----|----------|------|
| `pid_lock` | PID 分配器 | `kernel/process.c` |
| `parent_lock` | 进程父子关系 | `kernel/process.c` |
| `tickslock` | 系统滴答计数器 | `kernel/timer.c` |
| `p->lock`（每进程） | 进程状态、线程队列 | `kernel/process.c` |
| `t->lock`（每线程） | 线程状态 | `kernel/thread.c` |
| `lk` 参数（`sleep_on_chan`） | 调用者传入，原子释放+睡眠 | 各处 |

## 睡眠锁 (`kernel/sleeplock.c`)

### 数据结构

```c
struct sleeplock {
    uint locked;            // 1=已锁定
    struct spinlock lk;     // 保护 sleeplock 内部状态的自旋锁
    const char *name;       // 锁名称
    int pid;                // 持有锁的进程 PID
};
```

### 接口

```c
void initsleeplock(struct sleeplock *lk, const char *name);
void acquiresleep(struct sleeplock *lk);  // 获取睡眠锁（可能阻塞）
void releasesleep(struct sleeplock *lk);  // 释放睡眠锁
int  holdingsleep(struct sleeplock *lk);  // 检查是否持有
```

### 使用场景

睡眠锁用于可能长时间持有的锁，特别是磁盘 I/O 操作（如 `ext4_inode.c` 中的 inode 锁）。`acquiresleep()` 在锁被占用时会 `sleep_on_chan()`，让出 CPU。

### 与自旋锁的对比

| | 自旋锁 | 睡眠锁 |
|---|--------|--------|
| 等待方式 | 忙等（自旋） | 让出 CPU（睡眠） |
| 适用场景 | 短临界区 (< μs) | 长操作（磁盘 I/O） |
| 中断上下文 | 可用 | **不可用** |
| 持有期间 | 不可睡眠 | 可以睡眠 |
| 底层实现 | 硬件原子指令 | 自旋锁 + sleep_on_chan |

## 睡眠/唤醒机制 (`kernel/process.c`)

```c
void sleep_on_chan(void *chan, struct spinlock *lk);
void wakeup(void *chan);
```

### `sleep_on_chan` 语义

1. 调用者必须持有 `lk`。
2. 如果 `lk != &p->lock`，先获取 `p->lock`，再释放 `lk`（原子操作，防止 wakeup 丢失）。
3. 设置 `p->chan = chan`、`p->state = SLEEPING`。
4. 调用 `sched()` 让出 CPU。
5. 被唤醒后：恢复 `chan = 0`，重新获取 `lk`。

### `wakeup` 语义

1. 遍历进程池 `pool[NPROC]`。
2. 找到所有 `state == SLEEPING && chan == 目标 chan` 的进程。
3. 将其状态设为 `RUNNABLE`。

### 典型使用模式

```c
// 等待条件
acquire(&lk);
while (!condition) {
    sleep_on_chan(&channel, &lk);
}
// 条件满足，执行操作
release(&lk);

// 通知等待者
acquire(&lk);
condition = 1;
wakeup(&channel);
release(&lk);
```

### 常见 sleep channel

| Channel | 等待条件 | 唤醒者 |
|---------|----------|--------|
| `&ticks` | 定时器滴答 | 时钟中断 |
| `p`（进程指针） | 子进程退出 | `exit()` |
| `virtio` 相关 | 磁盘 I/O 完成 | `virtio_disk_intr()` |
| `sleeplock` 内部 | 锁释放 | `releasesleep()` |
| futex | 用户态互斥量 | `futex_wake()` |

## Futex (`kernel/futex.c`)

实现快速用户态互斥量（pthread 同步基础）。支持 `FUTEX_WAIT` 和 `FUTEX_WAKE` 操作。

`futex_clear()` 在调度器切换线程前调用，清理当前线程的 futex 等待状态。

## 后续开发任务

- 当前自旋锁没有公平性保证（可能饿死）。
- 多核环境下 `push_off`/`pop_off` 的嵌套计数需要 per-CPU 验证。
- `sleep_on_chan` 存在经典的 wakeup 丢失问题（如果 wakeup 发生在 `sleep_on_chan` 释放 lk 和获取 p->lock 之间）。当前通过先获取 p->lock 再释放 lk 缓解，但不完美。
- 睡眠锁没有超时机制。
- Futex 只实现了基本的 WAIT/WAKE，未支持 PI (Priority Inheritance) futex。
