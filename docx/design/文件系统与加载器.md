# 文件系统与加载器设计

项目：SOS (SuperOS)

队伍 ID：T2026104869910625

本文档说明 SOS 的 VFS 层、EXT4 原生实现、文件/Inode 对象、管道、块缓存、块设备抽象、ELF 加载器和用户程序启动流程。

## 设计目标

SOS 实现了**完整的 EXT4 文件系统**（读写支持），包含 Extent 树、HTree 目录索引、JBD2 日志、块分配器、Inode 分配器等核心组件。EXT4 是主力文件系统。VFS 层在此基础上提供统一接口，同时兼容 VFAT（只读）和 BusyBox 虚拟文件系统。

### ELF 加载器 (`kernel/exec.c`)

当前状态：~800 行，实现了完整的 ELF 加载流程。

**加载流程**:

```
exec(path, argv, env)
  → is_sh_script(path)              // 检测 .sh 后缀 → shebang 机制
    → 替换为 /musl/busybox sh 执行
  → namei(path)                     // 查找文件 inode
  → read elf_header                 // 读取并校验 ELF Magic
  → 遍历 program headers:
    ├─ PT_INTERP → 标记 is_dynamic=1，保存 interp 路径
    ├─ PT_PHDR   → 记录 at_phdr（auxv 用）
    └─ PT_LOAD   → uvm_grow() + loadseg() 加载段到内存
  → 处理动态链接:
    ├─ 读取 interp 段中的解释器路径
    ├─ namei() 查找解释器文件
    ├─ mmap() 分配解释器内存空间
    └─ load_interpreter() 加载解释器各 PT_LOAD 段
  → alloc_vma_stack(p)             // 分配用户栈
  → 构造用户栈:
    ├─ 随机数（AT_RANDOM）
    ├─ 环境变量字符串（envp）
    ├─ 参数字符串（argv）
    ├─ auxv 数组（AT_PHDR/AT_PHENT/AT_PHNUM/AT_BASE/AT_ENTRY/...）
    ├─ envp 指针数组
    └─ argv 指针数组
  → 设置 trapframe:
    ├─ a0 = sp（argc 地址）
    ├─ a1 = sp + 8（argv 地址）
    ├─ epc/era = program_entry（程序入口或解释器入口）
    └─ sp = 用户栈顶
  → 处理重定向（> 和 >>）
  → proc_freepagetable(&p_copy, oldsz)  // 释放旧进程资源
```

**动态链接器支持**:

| 解释器路径 | 架构 | C库 | 后续依赖 |
|-----------|------|-----|----------|
| `/lib/ld-linux-riscv64-lp64d.so.1` | RISC-V | glibc | libc.so.6, libm.so.6 |
| `/lib/ld-musl-riscv64-sf.so.1` | RISC-V | musl | libc.so |
| `/lib64/ld-linux-loongarch-lp64d.so.1` | LoongArch | glibc | libc.so.6 |
| `/lib64/ld-musl-loongarch-lp64d.so.1` | LoongArch | musl | libc.so |

**shebang 机制** (`is_sh_script()`):
```c
int is_sh_script(char *path) {
    int len = strlen(path);
    if (len < 3) return 0;
    if (path[len-1] == 'h' && path[len-2] == 's' && path[len-3] == '.')
        return 1;  // 检测 .sh 后缀
    return 0;
}
```
检测到 `.sh` 脚本时，替换执行路径为 `/musl/busybox`，设置 `argv[0]="busybox"`, `argv[1]="sh"`，原始脚本路径作为后续参数。

**重定向支持**：在 `exec()` 中扫描 argv，检测 `>`（REDIR_OUT）和 `>>`（REDIR_APPEND），关闭 stdout (fd 1)，用 `vfs_ext4_open` 重新打开目标文件。

### 用户态 initcode (`user/`)

**RISC-V** (`user/riscv/user.c`):
- 打开 `/dev/console` 作为 fd 0/1/2
- `execve("/musl/busybox", ["busybox", "sh", "test.sh"], env)`

**LoongArch** (`user/loongarch/user.c`):
- 同样流程，使用 LoongArch syscall 指令

编译后的 initcode 嵌入为 `unsigned char init_code[]`（通过 `.h` 文件包含）。

## 文件系统操作路径

```
用户态: open("/musl/busybox", O_RDONLY)
  → sys_openat()
    → vfs_ext4_openat()
      → ext4_namei()          // HTree 目录查找
        → ext4_inode_read()   // 读取 inode
          → ext4_extent_map() // Extent 树: 逻辑块号→物理块号
            → bread()         // 块缓存
              → blockdev_read() // 块设备抽象
                → virtio_disk_read() // VirtIO 块设备
```

## 与其他子系统的依赖

- `fs` ← `drivers`：块设备驱动提供 `blockdev_read/write`。
- `fs` ← `mm`：块缓存（bio）使用 `pmem_alloc_pages`；管道 buffer 在内核内存中。
- `fs` → `task`：进程的 `ofile[]` fd 表和 `cwd` 依赖 VFS。
- `fs` → `syscall`：所有文件类 syscall 的实现。
- `loader` ← `fs`：`namei()` 查找可执行文件和动态链接器。
- `loader` ← `mm`：`uvm_grow()`、`mmap()`、`mappages()` 映射 ELF 段。

## 后续开发任务

- EXT4 写操作（创建文件、写数据、分配块）的日志完整性在异常断电时未经过充分验证。
- Extent 树分裂逻辑在极端大文件和碎片化场景下可能出现边界 bug。
- 块缓存（NBUF）有固定上限，大量并发 I/O 时可能成为瓶颈。
- ELF 加载器对 PIE (Position Independent Executable) 的处理使用固定 `load_bias = 0x10000`，对 ASLR 不友好。
- 动态链接器加载依赖 `LD_LIBRARY_PATH` 的硬编码预设，用户自定义库路径可能冲突。
- VFAT 当前只是兼容层（只读），不支持写入。
