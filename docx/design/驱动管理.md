# 驱动设计

项目：SOS (SuperOS)

队伍 ID：T2026104869910625

本文档说明 SOS 的 UART、定时器、中断控制器、VirtIO 块设备驱动，以及双架构设备差异。

## 范围与原则

- 驱动代码分架构存放：`kernel/driver/riscv/`（RISC-V MMIO）和 `kernel/driver/loongarch/`（LoongArch PCI）。
- HAL 层的 UART 驱动与架构绑定（`hal/riscv/uart.c` 和 `hal/loongarch/uart.c`），通过 `console.c` 提供统一接口。
- 块设备通过 `blockdev.c` 统一抽象，EXT4 通过 `bread()`/`bwrite()` 访问，不直接依赖 VirtIO 细节。
- 双架构设备差异通过编译期条件编译处理。

## 当前已有文件分析

### UART 驱动

**RISC-V64** (`hal/riscv/uart.c`): NS16550 兼容 UART，MMIO 基址 `UART0 = 0x10000000`（QEMU virt）。
- `uartinit()` — 初始化 UART（设置波特率、使能 FIFO）
- `uartputc(int c)` — 输出一个字符
- `uartgetc()` — 获取一个字符（轮询）
- `uartintr()` — UART 接收中断处理 → `consoleintr()`

**LoongArch64** (`hal/loongarch/uart.c`): LoongArch 平台 UART，通过 `virtio_probe()` 发现。
- 同样的功能接口，MMIO 地址由 PCI 枚举确定。

### 控制台 (`kernel/console.c`)

```c
void chardev_init();       // → uartinit()
void consoleintr(int c);   // UART 输入字符处理（缓冲到 console buffer）
void consputc(int c);      // 输出字符（回显用）
```

### 定时器

**RISC-V64**: 通过 OpenSBI `sbi_set_timer()` 设置下一次定时器中断。
**LoongArch64**: 通过 CPU-local timer CSR（TCFG/TVAL/TICLR）管理 one-shot 定时器。

### 中断控制器

**RISC-V64**: PLIC (Platform-Level Interrupt Controller) 管理外部中断。`plicinit()` 初始化、`plicinithart()` 每 hart 初始化、`plic_claim()` 获取中断号。

**LoongArch64**: 内置中断控制器，通过 `estat` 和 `ecfg` 寄存器管理，不使用 PLIC。

### VirtIO 块设备

**RISC-V64** (`kernel/driver/riscv/virt.c`):
```c
void virtio_disk_init();       // 初始化 virtio-mmio 块设备
void virtio_disk_rw(struct buf *b, int write); // 读写扇区
void virtio_disk_intr();       // 中断处理
```

使用 virtio-mmio 传输层，通过 MMIO 寄存器（`VIRTIO0 = 0x10001000`）访问。QEMU 参数使用 `-device virtio-blk-device,drive=x0,bus=virtio-mmio-bus.0`。

**LoongArch64** (`kernel/driver/loongarch/`):
```c
void virtio_probe();           // PCI 枚举发现 virtio-blk-pci 设备
void la_virtio_disk_init();    // 初始化 virtio-pci 块设备
```

使用 virtio-pci 传输层。先通过 `virtio_pci.c` 进行 PCI 总线枚举，发现 virtio-blk 设备后通过 `virtio_disk.c` 进行块操作。QEMU 参数使用 `-device virtio-blk-pci,drive=x0`。

### PCI 枚举 (`kernel/driver/loongarch/pci.c`)

LoongArch 平台使用 PCI 总线连接 VirtIO 设备：
```c
void pci_init();               // PCI 总线初始化
uint32 pci_config_read(...);   // 读 PCI 配置空间
void pci_config_write(...);    // 写 PCI 配置空间
```

### 块设备抽象 (`kernel/fs/blockdev.c`)

```c
void blockdev_init();          // 初始化块设备
int blockdev_read(uint64 lba, void *buf, uint64 count);  // 读扇区
int blockdev_write(uint64 lba, const void *buf, uint64 count); // 写扇区
```

### 块缓存 (`kernel/fs/bio.c`)

```c
struct buf *bread(uint32 dev, uint32 blockno); // 读块（缓存命中直接返回）
void bwrite(struct buf *b);                     // 写块（标记脏，同步写回）
void brelse(struct buf *b);                     // 释放块引用
void binit();                                    // 初始化 NBUF 个 buffer
```

## QEMU 设备布局

### RISC-V64 (`qemu-system-riscv64 -machine virt`)

| 设备 | MMIO 基址 | IRQ | 说明 |
|------|-----------|-----|------|
| UART0 | `0x10000000` | 10 | NS16550 |
| VIRTIO0 | `0x10001000` | 1 | virtio-mmio |
| PLIC | `0x0c000000` | — | 中断控制器 |
| CLINT | `0x02000000` | — | 定时器（mtimecmp） |

### LoongArch64 (`qemu-system-loongarch64`)

| 设备 | 连接方式 | 说明 |
|------|----------|------|
| UART | PCI 枚举 | LoongArch UART |
| VirtIO Block | PCI 枚举 | virtio-blk-pci |
| VirtIO Net | PCI 枚举 | virtio-net-pci |
| Timer | CPU CSR | TCFG/TVAL/TICLR |

## 驱动初始化顺序 (`sos_start_kernel()`)

```c
// RISC-V 路径
plicinit();           // PLIC 中断控制器初始化
plicinithart();       // 当前 hart PLIC 初始化
virtio_disk_init();   // virtio-mmio 块设备初始化

// LoongArch 路径
virtio_probe();       // PCI 枚举 + 设备发现
la_virtio_disk_init(); // virtio-pci 块设备初始化

// 两条路径之后
init_fs();            // 依赖块设备
binit();              // 块缓存初始化
```

## 关键数据流

```
VFS 读文件
  → vfs_ext4_read()
    → ext4_inode_read()
      → ext4_extent_map()      // 逻辑块号→物理块号
        → bread(dev, blockno)
          → 查 block cache
            ├─ 命中 → 直接返回
            └─ 未命中 → blockdev_read()
              → virtio_disk_rw(b, 0)   // RISC-V
              → la_virtio_disk_rw(b, 0) // LoongArch
                → virtqueue 提交请求
                → 等待中断完成
                → 返回数据
```

## 与其他子系统的依赖

- `drivers` ← `arch`：MMIO 地址定义、PLIC/中断控制器寄存器地址。
- `drivers` → `fs`：通过 `blockdev` 抽象层提供块读写能力。
- `drivers` → `trap`：设备中断通过 `devintr()` 分发到 `virtio_disk_intr()`。
- `drivers` → `sync`：VirtIO 操作使用自旋锁保护 virtqueue。
- `drivers` → `logging`：UART 是最早的日志输出后端。

## 后续开发任务

- LoongArch 的 virtio-pci 路径在物理板卡（如 Loongson 2K1000LA）上 PCI 枚举可能发现额外设备，需要额外的设备 ID 匹配逻辑。
- UART 中断处理和内核日志输出共享同一设备，在高负载日志输出时可能丢失输入字符。
- VirtIO 的 DMA 地址转换在 LoongArch 上依赖 DMW 窗口，物理地址必须在窗口覆盖范围内。
- 块缓存的 LRU 策略较为简单（固定大小 NBUF），大量随机 I/O 时命中率下降。
