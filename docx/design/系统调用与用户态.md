# 系统调用与用户态 ABI 设计

项目：SOS (SuperOS)

队伍 ID：T2026104869910625

本文档说明 SOS 的系统调用层设计：ABI 约定、分发机制、已实现 syscall 列表、参数校验、错误码体系，以及与 Linux ABI 的兼容策略。

## 设计目标

竞赛评测使用预编译的 Linux ABI 用户程序（busybox、LTP、iozone），因此内核 syscall 层以 Linux 兼容为主线。第一阶段目标不是覆盖所有 Linux syscall，而是优先跑通基础测例、busybox 入口和 LTP 常用路径。

## 当前已有文件分析

### 系统调用分发 (`kernel/syscall.c`)

当前状态：~4605 行，是内核最大的单体文件。实现了 80+ 个系统调用，覆盖进程/文件/内存/时间/信号/epoll/eventfd/timerfd/pipe/ioctl 等。

**分发入口**：
```c
void syscall(struct trapframe *trapframe)
{
    // 从 trapframe 获取 syscall 编号（RISC-V: a7, LoongArch: $a7）
    // 从 trapframe 获取参数（a0-a5）
    // 查分发表 → 调用具体 sys_xxx()
    // 返回值写入 trapframe->a0
}
```

**ABI 约定**（双架构统一语义）：

| 含义 | RISC-V64 | LoongArch64 |
|------|----------|-------------|
| syscall 编号 | `a7` | `$a7` |
| 参数 0..5 | `a0..a5` | `$a0..$a5` |
| 返回值 | `a0` | `$a0` |
| 成功 | ≥ 0 | ≥ 0 |
| 失败 | `-errno` | `-errno` |

### 错误码体系

定义在 `include/kernel/errno-base.h`，与 Linux 标准错误码一致：

| 错误码 | 含义 | 典型触发条件 |
|--------|------|-------------|
| `EINVAL` | 无效参数 | fd < 0, flags 非法 |
| `EFAULT` | 无效用户空间地址 | copyin/copyout 失败 |
| `ENOMEM` | 内存不足 | pmem_alloc_pages 失败 |
| `ENOENT` | 文件/目录不存在 | namei 失败 |
| `EBADF` | 无效文件描述符 | ofile[fd] == NULL |
| `EACCES` | 权限不足 | access check 失败 |
| `EEXIST` | 文件已存在 | O_EXCL 创建 |
| `ENOTDIR` | 不是目录 | 对普通文件调用 getdents |
| `EISDIR` | 是目录 | 对目录调用 read/write |
| `EMFILE` | 进程 fd 用尽 | fdalloc 失败 |
| `ENFILE` | 系统文件表用尽 | filealloc 失败 |
| `ECHILD` | 没有子进程 | wait 时无子进程 |
| `ESRCH` | 进程不存在 | kill 不存在的 pid |
| `ENOSYS` | 系统调用未实现 | clone3 |
| `EROFS` | 只读文件系统 | 对 ro mount 写入 |
| `E2BIG` | 参数列表过长 | execve argv > MAXARG |
| `ENOSPC` | 磁盘空间不足 | ext4 block alloc 失败 |

## BusyBox 虚拟 /proc 文件系统

为兼容 busybox 工具，在内核 `sys_openat`/`sys_fstatat`/`sys_statx`/`sys_getdents64` 中实现了虚拟文件系统。核心函数：

| 函数 | 作用 |
|------|------|
| `is_busybox_virtual_path(path)` | 判断路径是否为虚拟路径 |
| `busybox_virtual_size(path)` | 返回虚拟文件大小 |
| `fill_busybox_virtual_kstat(path, st)` | 填充 struct kstat |
| `fill_busybox_virtual_statx(path, st)` | 填充 struct statx |
| `busybox_virtual_proc_pid_from_path(path, suffix)` | 解析 `/proc/[pid]/stat` 路径 |
| `normalize_proc_oom_score_adj_path(path)` | 处理 `/proc/self/oom_score_adj` 等路径 |
| `busybox_find_proc_by_pid(pid)` | 按 PID 查找进程（遍历 pool） |

支持的虚拟路径：
- `/proc`、`/proc/self` — 目录操作
- `/proc/mounts` — `df` 命令
- `/proc/meminfo` — `free` 命令
- `/proc/cpuinfo` — CPU 信息
- `/proc/self/stat`、`/proc/[pid]/stat` — `ps` 命令
- `/proc/self/status`、`/proc/self/exe`、`/proc/self/maps` — 进程信息
- `/proc/sys/kernel/pid_max` — PID 上限
- `/proc/sys/fs/pipe-user-pages-soft` — 管道限制
- `/etc/passwd`、`/etc/group` — 用户/组信息
- `/dev/misc/rtc` — `hwclock` 命令

## 关键实现细节

### sys_openat 路径（最复杂 syscall，~500 行）

```
sys_openat(fd, upath, flags, mode)
  → copyinstr(path)                      // 从用户空间拷贝路径
  → get_fs_from_path(path)               // 判断 EXT4 或 VFAT
  → get_absolute_path(path, cwd, abs)    // 解析绝对路径
  → normalize_proc_oom_score_adj_path()  // 处理 /proc/self 路径
  → reject_path_write_on_ro_mount()      // 检查只读挂载
  → filealloc() + fdalloc(f)             // 分配文件对象和描述符
  → is_busybox_virtual_path()            // 虚拟文件？→ FD_BUSYBOX
  → vfs_ext4_openat(f)                   // 真实 EXT4 打开
  → ext4_mode_set()                      // O_CREAT 时设置权限
  → 检查 /proc/mounts、/proc/meminfo 等 → 转为 FD_BUSYBOX
```

### sys_execve 路径（~200 行）

```
sys_execve(upath, uargv, uenvp)
  → copyinstr(path)                      // 拷贝程序路径
  → 处理 argv[]：fetchaddr→fetchstr     // 逐参数拷贝到内核页
  → 处理 envp[]：预设 LD_LIBRARY_PATH   // glibc/musl 库路径
  → exec(path, argv, envp)               // 加载 ELF
  → 清理 argv/envp 分配的临时页
```

### 路径处理模式

所有涉及路径的 syscall 遵循统一模式：
```c
char path[MAXPATH], absolute_path[MAXPATH];
copyinstr(p->pagetable, path, (uint64)upath, MAXPATH);
const char *dirpath = (fd == AT_FDCWD) ? p->cwd.path : p->ofile[fd]->f_path;
get_absolute_path(path, dirpath, absolute_path);
```

## 与其他子系统的依赖

- `syscall` ← `trap`：从 trapframe 提取 syscall 编号和参数，写回返回值。
- `syscall` ← `mm`：copyin/copyout 校验用户地址、brk/mmap/munmap。
- `syscall` ← `fs`：open/read/write/close/stat/getdents 等文件操作。
- `syscall` ← `task`：fork/clone/exec/exit/wait/kill 等进程操作。
- `syscall` ← `loader`：exec 委托给 exec.c 加载 ELF。
- `syscall` ← `timer`：nanosleep/gettimeofday/clock_gettime。

## 后续开发任务

- Linux ABI 不只是编号一致，还包括错误码语义、阻塞行为、文件描述符继承、路径解析和内存权限等细节。
- `sys_clone3` 返回 `-ENOSYS`，如果官方测试调用它会失败。
- epoll/eventfd/signalfd/timerfd 均为存根实现（创建 fd 但不处理实际事件），只满足 busybox 不崩溃的要求。
- LoongArch64 和 RISC-V64 使用不同的 syscall 编号体系（Linux LA64 vs Linux RV64），需要在 `syscall_ids.h` 中分别维护。
- BusyBox 虚拟文件系统的模拟值（如 `sysinfo.totalram`、`/proc/meminfo` 内容）可能与真实 Linux 不完全一致。
