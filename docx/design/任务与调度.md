# 任务、进程、线程与调度设计

项目：SOS (SuperOS)

队伍 ID：T2026104869910625

本文档记录 SOS 的进程管理、线程管理、上下文切换、调度器、PID/TID 分配、fork/clone/exec/exit/wait 生命周期和信号处理的目标设计。

## 设计目标

- 内核态 C 语言实现，不依赖动态内存分配用于核心调度数据结构（进程池/线程池均为静态数组）。
- 进程和线程的所有权分离：进程拥有地址空间和资源（文件描述符、VMA、信号处理器），线程拥有可运行的执行上下文（trapframe、内核栈、context）。
- 调度器采用轮转（round-robin）策略，线程作为调度基本单位。
- 支持 Linux 兼容的 1:1 线程模型（`CLONE_THREAD`）。

**进程状态机**:
```
UNUSED → USED → RUNNABLE ⇄ RUNNING → ZOMBIE
                    ↑          ↓
                  SLEEPING ←──┘
```

**调度流程** (`scheduler()`):
```
for (;;) {
    intr_on();
    for (p = pool; p < &pool[NPROC]; p++) {
        acquire(&p->lock);
        if (p->state == RUNNABLE) {
            // 遍历进程的 thread_queue，找 t_RUNNABLE 或 t_TIMING(已到期) 的线程
            // 设置 p->main_thread = 选中线程
            // 拷贝线程 context 和 trapframe 到进程级别
            // p->state = RUNNING, thread->state = t_RUNNING
            // cpu->proc = p
            // hsai_swtch(&cpu->context, &p->context)  → 切换到该进程
            // 返回后：保存线程状态，移到队列末尾（round-robin）
        }
        release(&p->lock);
    }
}
```

### 信号处理 (`kernel/signal.c`)

当前状态：实现了 POSIX 信号发送、信号集操作、sigaction 注册。

关键函数：
- `signal_should_terminate(signo)` — 判断信号是否需要终止进程（SIGKILL/SIGTERM/SIGABRT/SIGSEGV 等）
- `kill(pid, sig)` — 向目标进程设置 `sig_pending` 位，必要时设置 `killed`
- `tgkill(tgid, tid, sig)` — 向目标线程发送信号

### Futex (`kernel/futex.c`)

实现了快速用户态互斥量（pthread 同步基础），包括 `futex_wait` 和 `futex_wake` 操作。`futex_clear()` 在线程被调度前清理 futex 状态。

## 上下文切换设计

调度器只在持有 `p->lock` 的情况下执行切换：

```
yield() / sleep_on_chan() / exit()
  → acquire(&p->lock)
  → 修改 state/thread->state
  → sched()
    → copytrapframe(thread->trapframe, p->trapframe)   // 保存到线程
    → hsai_swtch(&p->context, &cpu->context)            // 架构切换
    → 返回后：cpu->proc = NULL
  → release(&p->lock)
```

关键约束：
- `TaskContext` 保存的是内核执行上下文（callee-saved 寄存器），不是完整用户 trap frame。
- `TrapFrame` 处理 exception/interrupt/syscall，在 trampoline 入口保存/出口恢复。
- 用户线程同时需要 context（调度用）和 trapframe（返回用户态用）。
- 切换用户进程时必须激活对应地址空间（`satp`/`pgdl` 写入由 trampoline 处理）。

## PID/TID 策略

- PID 从 1 开始单调递增（`allocpid()`），`Pid(0)` 作为非法哨兵。
- PID=1 预留给 init 进程（`initproc`，永不退出）。
- TID 从 1 开始全局唯一单调递增（`nexttid`），便于 wakeup 和调试查找。
- 任务表 slot index ≠ PID/TID。slot 通过遍历 pool 分配，PID 单独管理。

## 进程退出与回收

```
exit(exit_state)
  → 关闭所有 fd → reparent(子进程→initproc) → wakeup(parent)
  → p->state = ZOMBIE, p->main_thread->state = t_ZOMBIE
  → sched() （永不返回）

wait(pid, addr)
  → 遍历 pool 找 ZOMBIE 子进程 → freeproc(np) → 返回子进程 pid
  → 没有 ZOMBIE 子进程 → sleep_on_chan(p, &p->lock) 等待
  → 没有子进程 → return -ECHILD
```

`freeproc()` 释放：trapframe（物理页）、线程队列中每个线程的 trapframe 和独立内核栈、页表（`proc_freepagetable`）、文件描述符、VMA 链表。

## 与其他子系统的依赖

- `task` ← `mm`：fork 复制页表、exec 加载新页表、进程退出释放页表、内核栈分配。
- `task` ← `arch`：上下文切换汇编（`hsai_swtch`）、trapframe 操作（`copytrapframe`）。
- `task` ← `syscall`：fork/clone/exec/exit/wait/kill 等 syscall 实现。
- `task` ← `fs`：fd table 挂到进程状态上、cwd 管理。
- `task` ← `loader`：exec 调用 ELF 加载器、clone 从用户栈拷贝 `args_t`。
- `task` ← `sync`：自旋锁保护进程/线程状态、`sleep_on_chan`/`wakeup` 机制。

## 后续开发任务

- `SpinLock` 适合调度器内部短临界区，但持锁期间如果发生阻塞或调度器重入会导致死锁。
- 当前没有 generation counter，PID 复用后可能暴露陈旧句柄。
- `CLONE_VFORK` 当前降级为 eager-copy fork（`fork()` 而非阻塞父进程），不完全符合 Linux 语义。
- 进程池大小 NPROC=64 是硬限制，大量并发进程会耗尽。
- 线程池 THREAD_NUM 是编译期常量，动态线程创建受限。
- `freeproc()` 中主线程 trapframe 与进程 trapframe 共享同一物理页的判断依赖指针比较，容易在重构时引入 double-free。
