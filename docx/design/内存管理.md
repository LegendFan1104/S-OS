# 内存管理设计

项目：SOS (SuperOS)

队伍 ID：T2026104869910625

本文档说明 SOS 内存管理子系统的设计目标、模块边界、关键接口与实现细节。SOS 采用三级内存管理架构：Buddy System（物理页）→ SLAB 分配器（小对象）→ 多级页表（虚拟地址映射）+ VMA（虚拟内存区域管理）。

## 设计范围

- 物理页分配与回收（Buddy System）。
- 内核小对象快速分配（SLAB）。
- 多级页表遍历、映射、解映射（RISC-V 三级、LoongArch 四级）。
- 用户/内核地址空间管理（页表创建、VMA 链表、用户栈/堆增长）。
- 跨空间数据拷贝（copyin/copyout/copyinstr/fetchaddr/fetchstr）。

双架构差异通过 `#if defined RISCV` 条件编译集中在页表操作和权限位转换处，避免散落。

## 当前已有文件分析

### 物理内存管理 (`kernel/pmem.c`)

当前状态：实现了完整的 Buddy System（伙伴系统）。

核心接口：
```c
void *pmem_alloc_pages(int n);       // 分配 n 个连续物理页（零填充）
void  pmem_free_pages(void *p, int n); // 释放 n 个连续物理页
void  pmem_init();                     // 初始化 buddy 系统
void  buddy_safe_check();              // 诊断检查（debug 用）
```

全局状态：`buddy_system_t buddy_sys` 记录 mem_start、mem_end、各 order 的空闲链表。

设计要点：
- 物理内存范围来自链接脚本导出的 `USER_END` 符号和 QEMU `-m` 参数。
- 分配时先尝试多页连续分配（Buddy 的优势），失败则逐页回退。
- `debug_buddy` 全局变量控制 fork/exit 时的诊断输出。

### SLAB 分配器 (`kernel/slab_common.c`)

当前状态：实现了内核 SLAB 分配器，在 Buddy System 之上提供小对象快速分配。

核心接口：
```c
void *kalloc();         // 分配一个 SLAB 对象（用于 trapframe、thread_t 等）
void  kfree(void *p);   // 释放 SLAB 对象
void  slab_init();      // 初始化 SLAB 系统
```

设计要点：
- SLAB 从 Buddy System 获取底层物理页，内部划分为固定大小的槽位。
- `kalloc()` 用于分配 `trapframe`（`allocproc()` 中）、线程 trapframe（`alloc_thread()` 中）、内核栈扩展页（`clone_thread()` 中）等小对象。
- `pmem_alloc_pages(1)` 直接用于分配页表、用户内存页等整页对象。

### 虚拟内存管理 (`kernel/vmem.c`)

当前状态：实现了多级页表操作、跨空间拷贝、用户空间增长等完整功能。

**页表遍历**：
```c
pte_t *walk(pgtbl_t pt, uint64 va, int alloc);
```
- RISC-V：三级页表（`PT_LEVEL=3`），每级 512 entry，PTE 格式为 Sv39。
- LoongArch：四级页表（`PT_LEVEL=4`），使用 DMW 直接映射窗口访问物理内存。
- `alloc=1` 时如果中间页表缺失，自动分配新的物理页作为下级页表。

**页表映射/解映射**：
```c
int  mappages(pgtbl_t pt, uint64 va, uint64 pa, uint64 len, uint64 perm);
void vmunmap(pgtbl_t pt, uint64 va, uint64 npages, int do_free);
```
- `mappages()` 要求 `va` 和 `pa` 对齐，拒绝重复映射。
- `vmunmap()` 可选释放物理页（`do_free=1`），校验物理地址在 buddy 范围内。

**用户空间操作**：
```c
pgtbl_t uvmcreate();                              // 创建空用户页表
void    uvminit(proc_t *p, uchar *src, uint sz);  // 加载 initcode
int     uvmcopy(pgtbl_t old, pgtbl_t new, uint64 sz); // fork 时复制页表
uint64  uvmalloc(pgtbl_t pt, uint64 oldsz, uint64 newsz, int perm); // 增长用户空间
uint64  uvmdealloc(pgtbl_t pt, uint64 oldsz, uint64 newsz);         // 收缩用户空间
uint64  uvm_grow(pgtbl_t pt, uint64 oldsz, uint64 newsz, int xperm); // ELF 加载时增长
void    uvmfree(pgtbl_t pagetable, uint64 start, uint64 sz);          // 释放用户空间
```

**跨空间拷贝**：
```c
int copyin(pgtbl_t pt, char *dst, uint64 srcva, uint64 len);       // 用户→内核（任意地址）
int copyinstr(pgtbl_t pt, char *dst, uint64 srcva, uint64 max);    // 用户→内核（字符串）
int copyout(pgtbl_t pt, uint64 dstva, char *src, uint64 len);      // 内核→用户
int fetchaddr(uint64 addr, uint64 *ip);                            // 取一个字
int fetchstr(uint64 addr, char *buf, int max);                     // 取一个字符串
```

设计要点：
- `copyin`/`copyout` 处理非对齐地址和跨页拷贝（逐页 walkaddr + memmove）。
- LoongArch 使用 `dmwin_win0` 对物理地址做 DMW 窗口映射转换。
- `uvmcopy`（fork 用）跳过空页、处理 VMA 区域映射、特殊处理 RISC-V 动态链接地址 `0x000000010000036e`。

### VMA 虚拟内存区域 (`kernel/vma.c`)

当前状态：实现了完整的 VMA 链表管理。

核心接口：
```c
struct vma *vma_init(proc_t *p);                          // 初始化 VMA 环形链表
void        alloc_vma_stack(proc_t *p);                    // 分配栈 VMA
struct vma *vma_copy(proc_t *np, struct vma *parent_vma); // fork 时复制 VMA
int         vma_map(pgtbl_t src_pt, pgtbl_t dst_pt, struct vma *vma); // VMA 间映射复制
void        free_vma_list(proc_t *p);                      // 释放 VMA 链表
void        free_vma(proc_t *p, uint64 start, uint64 end); // 释放指定范围 VMA
```

VMA 描述进程地址空间中的各段：
```
┌─────────────┐ stack top (PGROUNDUP(sz))
│   Stack     │ ← alloc_vma_stack() 预留 USER_STACK_SIZE
│     ↓       │
│   Heap      │ ← brk (sys_brk)
│     ↑       │
│   BSS       │ ← ELF PT_LOAD memsz > filesz 部分
│   Data      │ ← ELF PT_LOAD 有文件内容部分
│   Text      │ ← ELF PT_LOAD 代码段
│  Interp     │ ← mmap 加载的动态链接器
│  Reserved   │ ← 0x10000 (PIE base)
│  NULL guard │ ← 0x0 (不映射，捕获 NULL 指针)
└─────────────┘ 0x0
```

### 内存布局常量 (`include/kernel/` 架构头文件)

**RISC-V64** (`include/hal/riscv/riscv_memlayout.h`):
```
MAXVA = 1L << 38
KERNEL_BASE = 0x80200000
TRAMPOLINE = MAXVA - PGSIZE
TRAPFRAME  = TRAMPOLINE - PGSIZE
KSTACK     = TRAPFRAME - (NPROC * 2 * PGSIZE)  // 每进程 2 页（栈 + 扩展页）
```

**LoongArch64** (`include/hal/loongarch/loongarch.h`):
```
MAXVA = 1L << 31  // DMW 直接映射窗口
KERNEL_BASE = 0x9000000000000000
TRAMPOLINE = MAXVA - PGSIZE
TRAPFRAME  = TRAMPOLINE - PGSIZE
KSTACK     = TRAPFRAME - (NPROC * (KSTACKSIZE))  // 每进程 6+2 页
DMWIN_MASK = 用于 MMIO 窗口地址转换
```

## 物理内存分配路径

```
用户态 malloc() / mmap()
  → sys_brk() / sys_mmap()
    → uvmalloc() / uvm_grow()   (vmem.c)
      → pmem_alloc_pages(n)     (pmem.c, Buddy System)
        → 物理页

内核对象分配
  → kalloc()                    (slab_common.c, SLAB)
    → pmem_alloc_pages(1)       (必要时从 Buddy 获取新 slab 页)
  → pmem_alloc_pages(1)         (直接整页分配：页表、用户内存)
```

## 页表权限位

| 权限 | RISC-V64 (PTE_*) | LoongArch64 (PTE_*) |
|------|------------------|---------------------|
| 有效 | `PTE_V` (1<<0) | `PTE_V` |
| 可读 | `PTE_R` (1<<1) | `PTE_V` 隐含可读，`PTE_NR` 禁止读 |
| 可写 | `PTE_W` (1<<2) | `PTE_W` |
| 可执行 | `PTE_X` (1<<3) | `PTE_NX` 禁止执行 |
| 用户态 | `PTE_U` (1<<4) | `PTE_PLV3`（PLV=3 用户态） |
| 脏位 | `PTE_D` (1<<7) | `PTE_D` |
| Trampoline | `PTE_R \| PTE_X` | `PTE_NX`（禁止执行）或可执行取决于 mapping |
| MapStack | `PTE_R \| PTE_W` | `PTE_NX \| PTE_P \| PTE_W \| PTE_MAT \| PTE_D \| PTE_PLV3` |

`flags_to_perm()` 函数（[exec.c:548-569](kernel/exec.c#L548-L569)）负责将 ELF segment flags 转换为体系结构页表权限。

## 初始化顺序

`sos_start_kernel()` 中的初始化顺序严格依赖：
1. `pmem_init()` — 物理内存必须先初始化（供后续所有分配使用）
2. `vmem_init()` — 配置内核页表、映射内核代码/数据/栈、激活页表
3. `slab_init()` — 在内核页表激活后初始化小对象分配器
4. 之后才能进行用户进程创建和调度

## 与其他子系统的依赖

- `mm` ← `config`：PAGE_SIZE、KSTACKSIZE、USER_STACK_SIZE、MAXVA 等常量。
- `mm` ← `arch`：PTE 格式、页表级别、TLB flush、DMW 窗口。
- `mm` → `task`：fork 复制页表、exec 加载新页表、进程退出释放页表。
- `mm` → `syscall`：copyin/copyout 校验用户地址、brk/mmap/munmap 实现。
- `mm` → `loader`：ELF 加载调用 uvm_grow/mappages/mmap。
- `mm` → `fs`：bio 块缓存使用物理页。

## 后续开发任务

- `uvmcopy` 目前是 eager copy（fork 时全量复制），未实现 COW。大进程 fork 开销高。
- Buddy System 在长时间运行后可能出现外部碎片。
- LoongArch 的 DMW 窗口（`dmwin_win0`）地址转换在物理地址超出窗口范围时会出错。
- VMA 链表遍历是 O(n)，大量映射区域时性能下降。
- `copyin`/`copyout` 不做地址空间锁定，极端并发情况下可能 TLB shootdown 不一致。
