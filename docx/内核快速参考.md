# S-OS 内核快速参考

> 用途：供后续开发、代码审查和新对话快速建立上下文。
>
> 适用仓库：`E:\oskernel2026-sos`
>
> 约定：源码优先于设计文档；如果文档和当前代码冲突，以当前代码和实际构建配置为准。

## 1. 项目定位

S-OS（SuperOS）是一个基于 xv6 思路扩展的 C 语言宏内核，支持 RISC-V64 和 LoongArch64。核心目标不是实现完整 Linux，而是提供足够的 Linux ABI、文件系统和硬件支持，以运行 BusyBox、musl/glibc 用户程序、LTP、libcbench、Lua 等测试程序。

这是宏内核：进程、调度、虚拟内存、系统调用、VFS、EXT4 和块设备驱动都运行在内核地址空间中。

整体分层如下：

```text
hal/                 架构启动、汇编入口、CSR、Trap、TLB、UART
  ↓
hsai/                架构差异适配：Trap、页表、用户态返回、PLIC、打印
  ↓
kernel/              共享内核：进程、线程、调度、内存、系统调用、信号
  ├── fs/             VFS、file、inode、EXT4、pipe、buffer cache、blockdev
  └── driver/         RISC-V / LoongArch 架构设备驱动
  ↓
user/                 嵌入式 initcode、syscall 汇编跳板、测试入口
```

## 2. 关键目录

| 目录 | 主要职责 |
|---|---|
| `hal/riscv/` | RISC-V 启动、SBI、Sv39、`uservec/userret`、上下文切换、PLIC 相关接口 |
| `hal/loongarch/` | LoongArch 启动、DMW、四级页表、TLB refill、`ertn` 返回、上下文切换 |
| `hsai/` | Trap 初始化和分发、缺页处理、用户态返回、物理内存硬件配置 |
| `kernel/process.c` | 进程生命周期、调度器、sleep/wakeup、fork/clone/exit/wait |
| `kernel/thread.c` | 静态线程池和线程分配 |
| `kernel/pmem.c` | Buddy 物理页分配和回收 |
| `kernel/slab_common.c` | 基于 Buddy 的内核小对象分配 |
| `kernel/vmem.c` | 多级页表、映射、用户地址拷贝、brk 相关内存增长 |
| `kernel/vma.c` | text/data/heap/stack/mmap/interpreter 的 VMA 管理 |
| `kernel/syscall.c` | Linux ABI 系统调用实现和总分发器 |
| `kernel/exec.c` | ELF、PIE、动态链接器、shebang、argv/envp/auxv |
| `kernel/fs/` | VFS、EXT4、VFAT 兼容层、pipe、buffer cache、块设备抽象 |
| `kernel/driver/riscv/` | RISC-V VirtIO-MMIO、JH7110 SD/MMC |
| `kernel/driver/loongarch/` | PCI、VirtIO-PCI、Loongson SATA/AHCI |
| `user/riscv/`、`user/loongarch/` | 两套 initcode、系统调用跳板和测试 profile |
| `include/` | 公共内核接口、架构头文件、Trap frame、EXT4 头文件 |
| `docx/` | 设计文档、测试文档、开发历史；部分内容可能落后于源码 |

仓库根目录的 `build/`、`user/build/`、`kernel-rv`、`kernel-la`、磁盘镜像和日志属于构建或测试产物，不是核心源码模块。

## 3. 启动和用户态进入路径

主线代码在 `kernel/sos_start_kernel.c`：

```text
架构 entry.S
  → RISC-V start.c / LoongArch 入口初始化
  → cpuinit、UART、proc/thread 初始化
  → pmem_init
  → vmem_init
  → slab_init
  → hsai_trap_init
  → PLIC / VirtIO / SDMMC / SATA 初始化
  → init_fs、binit、fileinit、inodeinit、vfs_ext4_init
  → init_process
  → scheduler
```

`init_process()` 把生成的 `rv_init_code.h` 或 `la_init_code.h` 中的用户程序映射到虚拟地址 0，并设置初始用户栈和入口地址。

第一个线程从 `forkret()` 进入用户态。`forkret()` 首次执行时完成：

1. 挂载根 EXT4。
2. 创建 `/dev`、`/proc`、`/tmp`、`/usr/lib` 等运行所需路径。
3. 初始化 futex。
4. 设置 init 进程的当前工作目录。
5. 调用 `hsai_usertrapret()`，经过 trampoline 返回用户态。

文件系统挂载放在 `forkret()` 而不是早期启动函数中，是因为挂载流程可能睡眠，必须在正常进程上下文中执行。

## 4. 双架构差异

| 项目 | RISC-V64 | LoongArch64 |
|---|---|---|
| 页表 | Sv39，三级页表 | 四级页表，软件 TLB refill |
| 用户系统调用 | `ecall` | `syscall 0` |
| 返回用户态 | `sret` | `ertn` |
| Trap PC | `sepc` | `era` |
| Trap 原因 | `scause/stval` | `estat/badv` |
| 用户页表 | `satp` | `pgdl/pgdh` |
| 地址映射特点 | 普通物理地址映射 | DMWIN0/DMWIN1 直接映射窗口 |
| 定时器 | SBI 或 RISC-V timer | `tcfg/tval/ticlr` CSR |
| QEMU 块设备 | VirtIO-MMIO | VirtIO-PCI |
| 开发板块设备 | JH7110 SD/MMC | Loongson SATA/AHCI |
| 外部中断 | PLIC | LoongArch 内置中断寄存器 |

两套架构统一使用以下 syscall 语义：

```text
系统调用号：a7
参数：a0-a5
返回值：a0
失败：-errno
```

Trap frame 的字段布局因架构不同，但 `hsai/` 为上层提供统一操作接口。架构相关汇编主要集中在 `hal/`，不过 `kernel/` 和 `vmem.c` 中仍存在条件编译分支。

## 5. 进程、线程和调度

进程拥有资源，线程拥有执行上下文，CPU 同时记录当前进程和当前线程：

```text
proc：页表、VMA、ofile[]、cwd、信号处理器、PID、父子关系
thread：Trap frame、内核栈、context、TID、futex 等待状态
cpu：当前 proc 和当前 thread
```

`myproc()` 和 `mythread()` 分别返回 CPU 上下文中的当前进程和当前线程。`p->main_thread` 仍保留为兼容性别名，但不再作为判断当前执行线程的唯一来源；调度器选中的线程会同步写入 `cpu_t.thread`。

当前使用静态资源池：

```text
NPROC = 256
THREAD_NUM = 4096
NOFILE = 128        每进程 fd 数
NFILE = 1024       全局 file 数
```

调度器在 `kernel/process.c` 中轮询进程池。持有进程锁时，`proc_update_state_locked()` 根据线程队列汇总进程状态：存在运行线程时为 `RUNNING`，没有运行线程但存在可运行或已到期的 `TIMING` 线程时为 `RUNNABLE`，否则为 `SLEEPING`；`thread_ready_locked()` 负责将到期的定时线程转为可运行。调度器选中线程后绑定 `cpu_t.proc` 和 `cpu_t.thread`，并在进程调度上下文与线程的 context/trapframe 之间同步；`sched()`、`yield()` 和 `sleep_on_chan()` 都会校验当前线程属于当前进程。

睡眠、唤醒、futex、信号和定时器路径以线程状态为主要状态源，并在状态变化后重新汇总进程状态，避免进程状态与线程状态分裂。`exit()` 会将进程内线程统一标记为僵尸，`thread_exit()` 只处理当前线程；线程池回收由 `free_thread_lock` 保护，TID 分配由独立的 `tid_lock` 保护，同时分配和回收路径会清空线程的上下文、栈和归属字段。

进程创建路径：

- `fork()`：复制整个地址空间和 VMA，当前使用 eager copy。
- `sys_clone()` + `CLONE_VM`：创建同一进程内的新线程。
- `sys_clone()` 不带 `CLONE_VM`：创建新的进程式地址空间副本。
- `clone3()`：当前返回 `-ENOSYS`。

同步原语包括自旋锁、睡眠锁、`sleep_on_chan()`/`wakeup()` 和 futex。futex 当前主要支持 `WAIT`、`WAKE`、`REQUEUE`，服务于 musl/glibc 线程库。

线程相关系统调用和阻塞路径使用真实的当前线程：`gettid`、`set_tid_address`、`sigprocmask`、`futex`、`nanosleep` 和 `ppoll` 不再通过 `p->main_thread` 代指当前线程，信号 pending/mask、futex 等待和清理状态因此与实际执行线程保持一致。

## 6. 内存管理

```text
Buddy System
  → SLAB 小对象
  → 多级页表
  → VMA 虚拟内存区域
```

关键行为：

- Buddy 管理物理页和页块合并。
- SLAB 为 Trap frame、线程结构等内核对象提供小对象分配。
- `vmem.c` 负责页表遍历、映射、解除映射和 `copyin/copyout/copyinstr`。
- `vma.c` 使用环形链表管理代码、数据、堆、栈、mmap 和动态解释器区域。
- `mmap()` 当前会主动准备页面，文件映射不是完整 lazy fault 模式。
- 缺页处理支持 heap/VMA 页面分配，以及 LoongArch dirty bit 修正。
- `fork()` 当前没有 Copy-on-Write。

当前内存层的主要改进方向是：COW、lazy mmap、页表并发保护、TLB shootdown、VMA 查找结构优化和更严格的权限检查。

## 7. Trap、系统调用和信号

Trap 主线：

```text
硬件异常/中断
  → hal trampoline 或 kernelvec
  → 保存寄存器到 trap frame
  → hsai usertrap/kerneltrap
  → devintr / syscall / page fault / signal
  → hsai_usertrapret
  → userret
  → sret 或 ertn
```

`kernel/syscall.c` 是一个较大的单体文件，覆盖：

- 进程：fork、clone、execve、wait、exit、kill
- 文件：openat、read、write、close、dup、fcntl、pipe
- 目录：mkdirat、getdents64、unlinkat、renameat2、symlinkat
- 内存：brk、mmap、munmap、mprotect、mremap
- 时间：clock_gettime、nanosleep、gettimeofday、定时器
- 信号：sigaction、sigprocmask、kill、tgkill
- 同步：futex
- 事件 fd：epoll、eventfd、signalfd、timerfd、pidfd
- 网络接口：socket、bind、listen、accept、sendto、recvfrom

其中部分事件 fd 目前是兼容性存根，不具备完整 Linux 语义。系统调用层的后续重点是拆分文件、完善真实阻塞行为、补齐 `clone3`/poll/epoll/eventfd/timerfd 等 ABI。

## 8. VFS、EXT4 和块设备

文件访问路径：

```text
sys_openat/read/write
  → file table / fd table
  → file_vnode
  → inode operations
  → VFS EXT4
  → extent / inode / directory
  → bread/bwrite
  → buffer cache
  → blockdev
  → VirtIO / SDMMC / SATA
```

VFS 使用 `file`、`file_vnode`、`inode_operations` 和 `file_operations` 抽象普通文件、目录、设备、管道、socket 和虚拟文件。

EXT4 代码包含：

- inode 分配和读写
- block allocator / inode allocator
- extent tree
- 目录项和 HTree 索引
- bitmap、superblock、metadata checksum
- xattr
- journal/transaction 代码

但是当前 `include/kernel/fs/ext4_config.h` 中 `CONFIG_JOURNALING_ENABLE` 默认值为 0，所以当前构建不能视为已经启用完整 journaling。

`kernel/fs/file.c` 内置了 BusyBox 所需的虚拟 `/proc` 内容，包括 `/proc/meminfo`、`/proc/mounts`、`/proc/self/maps`、`/proc/[pid]/stat` 等。它不是独立的通用 procfs 实现。

设备路径：

- RISC-V QEMU 使用 VirtIO-MMIO + PLIC。
- RISC-V 开发板使用 JH7110 SD/MMC，编译开关为 `SDMMC_DRIVER=1`。
- LoongArch QEMU 使用 PCI 枚举和 modern VirtIO-PCI。
- LoongArch 开发板使用 SATA/AHCI，编译开关为 `SATA_DRIVER=1`。
- LoongArch VirtIO 块设备目前主要通过轮询完成请求，外部硬件中断分支仍不完整。

仓库中有 socket 系统调用，但没有完整 VirtIO-net/TCP/IP 协议栈。当前 `syscall_net.c` 使用固定大小的内存 packet store 做兼容性实现。

## 9. ELF 加载器和用户态

用户态编译流程：

```text
user.c + usys.S
  → user.out
  → user.bin
  → C 数组头文件
  → include/kernel/rv_init_code.h 或 la_init_code.h
  → 内核嵌入 initcode
```

`kernel/exec.c` 支持：

- ELF header 和 PT_LOAD
- PIE 程序固定 load bias
- PT_INTERP 动态链接器
- glibc/musl 解释器路径
- `.sh`/shebang 交给 BusyBox
- argv、envp、auxv、AT_RANDOM、AT_PHDR、AT_BASE、AT_EXECFN
- 用户栈和 Trap frame 初始化

用户入口通过 `run_selected_profile()` 选择 smoke、submit、probe、buildstorm、starry、ltp-musl 或 ltp-glibc。当前源码直接在 `user.c` 中选择测试逻辑，部分旧文档中描述的 `test.sh` 流程已经过时。

## 10. 当前边界

以下内容不能只根据设计文档中的“已支持”描述判断：

1. 进程、线程和调度器已完成一轮状态一致性修复，但仍需在多核、多线程、睡眠唤醒、信号和线程回收压力场景下继续验证。
2. `fork()` 没有 COW，大进程创建开销较高。
3. VMA 是链表，页表并发和多 CPU TLB 同步能力有限。
4. EXT4 journaling 默认关闭，异常断电一致性需要单独验证。
5. VFAT 主要是兼容层，不能按完整可写 VFAT 使用。
6. epoll、eventfd、signalfd、timerfd、pidfd 中有存根实现。
7. `clone3()` 未实现。
8. socket 是兼容性数据路径，不是完整网络栈。
9. LoongArch 外部硬件中断处理仍需完善。
10. 进程、线程、文件和 buffer cache 容量均有静态上限。
11. `kernel/syscall.c` 过大，架构条件编译仍分散在共享内核中。

## 11. 后续完善优先级

按推荐顺序：

1. 对已完成的进程/线程/调度器一致性修复进行 RV/LA 多核回归，重点覆盖多线程创建销毁、futex、信号、sleep/wakeup 和 exec/exit 交错场景。
2. 修复 fd、inode、vnode、socket、pipe 和 exec/exit 路径的资源生命周期。
3. 实现 COW fork，完善 VMA、缺页和页表并发保护。
4. 完善 futex、信号和线程退出语义。
5. 拆分 syscall 单体文件，补齐真实的 poll/epoll/eventfd/timerfd/clone3 语义。
6. 验证并启用 EXT4 journaling，修复异常写入和重新挂载一致性。
7. 完善 LoongArch 外部中断、VirtIO 请求完成、DMA 和超时恢复。
8. 建立 RV/LA 双架构自动回归测试，覆盖多进程、多线程、动态链接和文件写入。
9. 清理 HAL/HSAI 边界，减少共享代码中的 `#if RISCV`。
10. 最后再做 VMA、调度器、buffer cache、任务表和网络栈的性能/扩展优化。
